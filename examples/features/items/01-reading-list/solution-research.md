## Decision-ready summary

Списки лучше хранить отдельно от карточки книги. Поле «списки» на самой книге смешивает избранное и именованные списки. Решение не принято.

## Problem / scope

Читатель на странице книги добавляет её в список. Пустой список должен быть понятен. Избранное сердечком не трогаем.

## Confirmed current state

На странице книги есть сердечко. Оно пишет книгу в избранное этого читателя. Именованных списков нет.

## Current-state architecture

См. [current-state.puml](./current-state.puml). Витрина зовёт Book API, тот пишет id книги в массив избранного.

## Impact map

| Слой | Что задето |
|------|------------|
| Web | кнопка и пустой экран |
| Book API | только если список живёт в карточке книги |
| Новый контур списков | если список — отдельная сущность |
| Избранное | не менять |

## Options

### Option 1

Поле `listIds` на документе книги. Быстро для одной книги, плохо для «мои списки» читателя.

### Option 2

Отдельное хранилище: список принадлежит читателю и ссылается на книги.

## Comparison

| | Option 1 | Option 2 |
|--|----------|----------|
| Пустой список | неудобно: пустой список не является книгой | естественный объект |
| Избранное | легко перепутать | остаётся как есть |

## Recommended option

Option 2. Это рекомендация, не решение.

Схема — [target-state.puml](./target-state.puml). В заголовке схемы написано, что это recommendation.
