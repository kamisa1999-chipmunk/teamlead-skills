# Action items — личные обязательства тимлида

## Назначение

Вести **только обязательства Камиллы** — не задачи команды и не договорённости сотрудников.

**Куда пишет:** `notes/leadership/kamilla-saidova.md` → `## Мои action items`

Вымышленный образец секции — `examples/leadership/teamlead.md` (от этой папки: `../../examples/`).

## Связка с другими скиллами

| Скилл | Когда вызывать `action-items` |
|-------|-------------------------------|
| **`1-1`** (фиксация 1:1) | **Всегда** после записи итогов — проверить конспект на обязательства тимлида |
| **`observations`** | Если пользователь просит **проверить встречу(и)** целиком или явно — экшен айтемы |
| **`meeting-context`** | По запросу «проверь встречи» вместе с observations |
| **`action-items`** | Прямой вызов: записать, обновить, закрыть, сверить список |

```
конспект / голос  →  action-items  →  kamilla-saidova.md § Мои action items
         ↑
1-1, observations (при разборе встреч)
```

Подробности распознавания — [reference.md](reference.md). Примеры — [examples.md](examples.md).

## Формат записи

Секция `## Мои action items` в `kamilla-saidova.md`:

- `_Обновлено: ДД.ММ.ГГГГ_` — дата последнего изменения
- **`### В работе`** — только чекбоксы `- [ ] ...`
- **`### Сделано — ДД.ММ.ГГГГ`** — чекбоксы `- [x] ...` (группировать по дате закрытия)
- **`### Потом / не сейчас`** — тоже чекбоксы `- [ ] ...`

Формат открытого пункта:

```markdown
- [ ] [задача] — **срок:** [срок или `-`]; **статус:** [в работе / ждём / частично / —]; **источник:** [откуда]
```

**Статусы:** `в работе` | `ждём` (входящее / блокер) | `частично` | `—`

**Приоритет** отдельным полем не обязателен; если критично — добавлять в текст задачи: `(высокий)` или уточнять срок.

Правила:
- **Дописывать**, не перезаписывать историю
- **Не дублировать** — перед добавлением прочитать «В работе»; похожее → обновить существующий чекбокс
- **Источник** обязателен: `1:1 Максим 08.07`, `daily 08.07`, `встреча с Валей 08.07`, `вручную 08.07`
- Action items **сотрудников** остаются в `teams/…` — сюда не копировать

## Сценарий 1: Записать вручную

**Триггеры:** «запиши экшен айтем», «добавь в мои action items», «зафиксируй, что я должна…»

### Шаги

1. Прочитать `kamilla-saidova.md` → `## Мои action items`.
2. Разобрать ввод пользователя на поля: **задача**, **срок**, **статус**, **источник**.
3. **Уточнить недостающее** (см. «Уточняющие вопросы») — не писать в файл, пока нет минимума.
4. Проверить дубликаты в «В работе».
5. Добавить чекбокс в список; обновить `_Обновлено_`.
6. Показать краткое резюме: что добавлено / обновлено.

**Минимум для записи:** задача + источник (`вручную ДД.ММ.ГГГГ`, если не назван).

## Сценарий 2: Из конспекта встречи

**Триггеры:** «вытащи мои экшен айтемы», «проверь экшен айтемы с встречи», вызов из `1-1` / `observations`

### Шаги

1. Прочитать конспект целиком (или переданный фрагмент).
2. Определить дату встречи (первая строка или имя файла).
3. Найти обязательства тимлида — см. [reference.md](reference.md) «Как распознавать».
4. Для каждого кандидата — черновик чекбокса.
5. Сверить с текущим «В работе» — новое / обновление / уже есть.
6. **Уточнить** у пользователя неясные сроки и статусы **одним блоком** (не по одному, если пунктов ≤5).
7. После ответа (или «запиши как есть») — записать в файл.
8. В резюме: список добавленных + «уточни позже: …» для открытых вопросов.

**Не записывать без подтверждения**, если формулировка двусмысленна (обещание vs намерение).

---

## Сценарий 3: Пакетная проверка встреч

**Триггеры:** «проверь встречи за сегодня», «собери мои экшен айтемы за 08.07», несколько файлов `.txt`

### Шаги

1. Список конспектов (из запроса или `~/Downloads/` за дату).
2. Для каждого файла — сценарий 2 (извлечение).
3. Объединить, убрать дубли между встречами.
4. Один блок уточнений по всем неясным пунктам.
5. Записать; показать сводку «найдено / добавлено / уже было».

---

## Сценарий 4: Закрыть или обновить

**Триггеры:** «сделала MM-группы», «закрой экшен айтем», «обнови статус», «перенеси на следующую неделю»

### Шаги

1. Найти чекбокс в «В работе» (по ключевым словам).
2. **Закрыто** → `- [x] …` в «Сделано — ДД.ММ.ГГГГ», удалить из «В работе».
3. **Изменён срок/статус** → правка строки, не новая дублирующая.
4. Обновить `_Обновлено_`.

---

## Сценарий 5: Сверка списка

**Триггеры:** «какие у меня открытые экшен айтемы», «что я обещала», «приоритизируй мои задачи»

### Шаги

1. Прочитать `## Мои action items`.
2. Показать «В работе» + «Потом» в удобном виде (можно сгруппировать по сроку).
3. По запросу — предложить приоритеты, **не меняя файл** без подтверждения.

## Уточняющие вопросы

Спрашивать **только то, чего нет** в конспекте или в сообщении пользователя.

| Поле | Когда спрашивать | Пример вопроса |
|------|------------------|----------------|
| **Срок** | нет даты/недели/«до отпуска» | «К какому сроку? сегодня / эта неделя / до 20.07?» |
| **Статус** | неясно, ждёшь ли ты кого-то | «Это в работе или ждём входящее (от Вали / от Насти)?» |
| **Критичность** | много пунктов, нужна очередь | «Что из этого сделать в первую очередь сегодня?» |
| **Формулировка** | размытое «разберёмся» | «Это твоя задача или общая договорённость с Костей?» |

Если пользователь торопится: записать с `-` в сроке и пометкой `(уточнить срок)` в задаче.

Использовать `AskQuestion` при 2–4 вариантах ответа; иначе — короткий текст в чате.

## Чего не делать

- Не класть сюда задачи сотрудников (`Руслан —`, `Максим —` в их файлах).
- Не удалять закрытые пункты из «Сделано».
- Не выдумывать обязательства, которых нет в конспекте.
- Не пропускать проверку при фиксации 1:1 (интеграция обязательна).
- Не дублировать блок `Камилла —` из `teams/` без проверки — там может быть устаревшее.

## Интеграция для других скиллов

**`1-1`, сценарий 1:** после шага 9 (peer feedback), перед резюме — выполнить **сценарий 2** этого скилла на том же конспекте. В резюме 1:1 добавить строку: «Мои action items: …» или «новых нет».

**`observations`, сценарий 1:** если в запросе есть «проверь встречу», «проверь встречи», «и экшен айтемы» — после наблюдений выполнить сценарий 2 или 3.
