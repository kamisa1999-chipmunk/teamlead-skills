# Источники для Feature-assessment

Читать **на шаге исходных материалов**, до нормализации и поиска. Не читать в начале прогона «на всякий случай». Не меняет ownership, research и формат ответа.

Способ чтения не привязан к конкретной локальной реализации. Skill одинаково работает, если Jira/Confluence доступны через MCP / connector / встроенный tool **или** через локальный Python CLI из репозитория.

## Выбор источника

Перед первым чтением Jira и перед первым чтением Confluence в этом прогоне — отдельно для каждой системы:

1. Использовать уже доступный в окружении источник (MCP, connector, встроенный tool), если он умеет прочитать нужный объект.
2. Если подходящего источника нет — локальный fallback из репозитория.

Не смешивать несколько источников одного артефакта без необходимости. Источник системы выбрать один раз за прогон и не менять без причины. Не перечитывать один артефакт повторно: после чтения свернуть в короткий summary.

Токены не читать и не показывать. Этим скиллом страницы, задачи и треды не изменять.

## Что принимает skill

Любой набор, не обязательно полный:

- текст (сообщение, голосовая расшифровка, заметка);
- screenshot (тред, список пунктов, фрагмент Jira / Confluence);
- ссылка (Jira, Confluence, обсуждение);
- Jira key / существующая Story;
- дополнительный комментарий пользователя.

Не требовать заранее заполненную карту ответственности.

## Приоритет комментария пользователя

Комментарии пользователя этого прогона имеют высокий приоритет относительно текста треда, скрина и предложенного автором решения.

Пример:

```text
Вот скрин. Пункт 2 точно наша зона ответственности, остальные под вопросом.
```

В таком случае:

- пункт 2 считать подтверждённым ownership (`OURS_CONFIRMED`);
- остальные не назначать другим командам без подтверждения;
- можно предположить ownership по контексту, но маркировать как гипотезу (`INFERENCE` / `OURS_LIKELY` / `UNKNOWN`).

Комментарий пользователя ≠ командное решение. Это `USER_INPUT`: учитывать как указание для этого assessment, не писать «команда подтвердила» / «в обсуждении решили», если в источниках этого нет.

## Screenshot

Если приложен screenshot — прочитать изображение. Зафиксировать:

- какие пункты / инициативы на нём видны;
- что является потребностью, а что предложенным способом;
- нумерацию, чтобы комментарий пользователя («пункт 2») можно было сопоставить.

Не домысливать нечитаемые фрагменты. Если часть скрина не разобрать — `OPEN_QUESTION`, не выдавать OCR-догадку за факт.

Скриншот описывать как запрос и поведение, не как утверждённую архитектуру.

## Jira / Story / ссылки

**Jira issue:** key, summary, description, type, status, links / parent / epic, labels, components; comments — если помогают понять проблему, ограничения, уже предложенный способ или ownership.

Существующая Story — один из источников, не истина и не выбранное решение.

**Confluence:** title, URL, актуальное содержимое; version / date — при наличии. Найденная страница не считается автоматически актуальной.

**Локальные notes:** только явно связанные файлы (`notes/features/…`). Не читать весь `features/` и весь `teams/`. Не читать карточки людей ради ownership.

Если обсуждение (Mattermost и т.п.) недоступно по ссылке — не выдумывать содержимое. Зафиксировать ссылку и при необходимости попросить вставить фрагмент или скрин.

## Неполные данные

Если выбранный MCP / connector / tool не отдаёт нужные поля:

- точечно добрать другим доступным способом (другой tool той же системы или local CLI fallback);
- не перечитывать уже полученные поля;
- если добрать нельзя — `OPEN_QUESTION` / `ASSUMPTION`, не выдавать отсутствие данных за факт.

Отсутствие поля в ответе источника ≠ «поля нет в системе».

## Local CLI fallback

Только если подходящего MCP / connector / tool нет или им нельзя добрать нужные поля.

Jira:

```bash
python3 notes/jira/scripts/cli/get_issue.py CAT2-XXXX
python3 notes/jira/scripts/cli/search_issues.py --jql '...' --limit 20
```

Confluence по `pageId`:

```bash
python3 ~/.cursor/skills/sa-review/scripts/dump_confluence_page.py PAGE_ID
```

Поиск Confluence:

```bash
python3 ~/.cursor/skills/sa-spec/scripts/search_confluence.py --title "..."
python3 ~/.cursor/skills/sa-spec/scripts/search_confluence.py --cql 'space = BIZ AND title ~ "..."'
```

Скрипты не копировать в `feature-assessment`. Сырые выгрузки, если CLI их создаёт, — в `notes/jira/tmp/` (не в git). После прогона удалить файлы этого запуска. Не коммитить их.

Запись в Jira этим скиллом не делать.
