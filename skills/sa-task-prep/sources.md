# Источники для SA-task-prep

Читать **на шаге исходных материалов**, до целевого поиска. Не читать в начале прогона «на всякий случай». Не меняет формат SA Task.

Способ чтения не привязан к конкретной локальной реализации. Skill одинаково работает, если Jira/Confluence доступны через MCP / connector / встроенный tool **или** через локальный Python CLI из репозитория.

## Выбор источника

Перед первым чтением Jira и перед первым чтением Confluence в этом прогоне — отдельно для каждой системы:

1. Использовать уже доступный в окружении источник (MCP, connector, встроенный tool), если он умеет прочитать нужный объект.
2. Если подходящего источника нет — локальный fallback из репозитория.

Не смешивать несколько источников одного артефакта без необходимости. Источник системы выбрать один раз за прогон и не менять без причины. Не перечитывать один артефакт повторно: после чтения свернуть в короткий summary.

Токены не читать и не показывать. Этим скиллом страницы и задачи не изменять.

## DeliveryStory — основной источник

Из неё взять:

- цель;
- ожидаемое поведение;
- scope / out of scope;
- ограничения;
- открытые вопросы;
- идеи / гипотезы для анализа;
- ссылки на источники.

Не дублировать Story полностью.

Нужные поля Jira: key, summary, type, status, description, links / parent / epic, labels; comments — если уточняют ограничения, гипотезы или решения. Связанные Analysis — проверить до создания новой задачи.

Дополнительные комментарии пользователя — второй источник того же уровня. Не подменять ими Story. Не дописывать в Story недостающее продуктовое поведение.

Комментарий пользователя в текущем диалоге ≠ обсуждение и ≠ согласованное решение. Если пользователь или разработчик подтвердил технический факт — confirmed current state, не формулировать его повторно как предмет анализа. Если идея, предпочтение или гипотеза пришли напрямую от пользователя, так и фиксировать: `есть предпочтение`, `пользователь предлагает рассмотреть`, `гипотеза`, `предпочтительное направление для анализа`. Не повышать `предпочтение` до `constraint` или `requirement` без подтверждения.

## Что ещё можно взять на этом шаге

**Прямые ссылки из Story** — только список. Содержимое страниц и связанных задач читать на шаге `research.md`.

**Локальные notes:** только явно связанные файлы (`notes/features/…`). Не читать весь `features/` и весь `teams/`. Чек-лист закрытия SA (`notes/teams/sa/checklist-close-sa.md`) в постановку не копировать; достаточно знать, что критерий завершения на него ссылается.

## Продуктовые пробелы в Story

По умолчанию не останавливаться и не предлагать `story-prep`.

Пробелы вроде:

- ожидаемое поведение неполное или заменено технической схемой;
- цель есть, но размыты scope / edge cases / кто управляет настройкой;
- конфликтующие требования без выбора;
- открытые продуктовые вопросы, без ответа на которые нельзя выбрать техническое решение.

→ открытые вопросы в SA Task. Аналитик уточнит их у продукта до реализации решения. Story не переписывать.

Техническая неопределённость (какой сервис, какой контракт, какой вариант реализации) — тоже работа SA Task, не пробел Story.

`story-prep` — только если Story нет (Epic / хотелка / Feature без постановки) или карточка пустая: нет цели и описания, постановку анализа сформулировать нельзя.

## Неполные данные

Если выбранный MCP / connector / tool не отдаёт нужные поля:

- точечно добрать другим доступным способом (другой tool той же системы или local CLI fallback);
- не перечитывать уже полученные поля;
- если добрать нельзя — открытый вопрос, не выдавать отсутствие данных за факт.

Отсутствие поля в ответе источника ≠ «поля нет в системе».

## Local CLI fallback

Только если подходящего MCP / connector / tool нет или им нельзя добрать нужные поля.

Jira:

```bash
python3 notes/jira/scripts/cli/get_issue.py CAT2-XXXX
python3 notes/jira/scripts/cli/search_issues.py --jql '...' --limit 20
```

Confluence по `pageId`:

```bash
python3 ~/.cursor/skills/sa-review/scripts/dump_confluence_page.py PAGE_ID
```

Поиск Confluence:

```bash
python3 ~/.cursor/skills/sa-spec/scripts/search_confluence.py --title "..."
python3 ~/.cursor/skills/sa-spec/scripts/search_confluence.py --cql 'space = BIZ AND title ~ "..."'
```

Скрипты не копировать в `sa-task-prep`. Сырые выгрузки, если CLI их создаёт, — в `notes/jira/tmp/` (не в git). После прогона удалить файлы этого запуска. Не коммитить их.

Запись в Jira — только через скилл `jira-write` после подтверждения.
