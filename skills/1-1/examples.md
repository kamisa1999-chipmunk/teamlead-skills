# Примеры — скилл 1:1

## Сценарий 1: Фиксация из конспекта

### Ввод пользователя

```
@1-1 зафиксируй результаты этого 1:1

/Users/saidova_k/Downloads/2026-07-03 0959 (MSK) 0108750527.txt
```

### Фрагмент конспекта

```
Встреча проходила 03.07.2026 с 09:59 (MSK). ...

Кафанова Мария Александровна:
[00:05:12] С задачами справляюсь нормально, но в админке пока тяжело.

Саидова Камилла Зарифовна (голос 1):
[00:05:30] Давай на следующей неделе возьмёшь CAT2-3700.

Кафанова Мария Александровна:
[00:05:45] Ок, возьму.
```

### Что делает агент

1. Дата: `03.07.2026`
2. Участники: Саидова + Кафанова → 1:1 с **Кафановой Марией**
3. Ищет карточку → `notes/teams/sa/maria-kafanova/`
4. Добавляет в `## 1:1 встречи`:

```markdown

03.07.2026
  * **Темы:**
    * текущие задачи
    * развитие в админке
  * **Сложности / блокеры:**
    * в админке пока тяжело
  * **Обратная связь:**
    * с задачами справляется нормально
  * **Договорённости:**
    * возьмёт CAT2-3700 на следующей неделе
  * **Action items:**
    * Мария — CAT2-3700 на следующей неделе
```

5. Сообщает: «Добавил запись 03.07.2026 в `teams/sa/maria-kafanova/1-1.md`»

### Важно

- Пользователь не пересказывает встречу — только даёт файл и команду.
- Агент сам определяет **кого** и **когда** по конспекту.
- После фиксации агент предлагает **разбор в коучинговом формате** (сценарий 1б).

## Сценарий 1б: Разбор и коучинг после 1:1

### Ввод пользователя

```
зафиксируй 1:1 и разбери как я провела

/Users/saidova_k/Downloads/2026-06-23 1000 (MSK) 0108750527.txt
```

Или после фиксации:

```
да, разберём
```

### Что делает агент

**1. Фиксация** (сценарий 1) — запись в `dmitry-guminichenko/1-1.md`.

**2. Рефлексия (R1)** — 2–3 вопроса:

> Что больше всего запомнилось? Как ты сейчас оцениваешь его прогресс?

Пользователь:

> В целом довольна, но кажется, я много говорила про peer feedback и он мало успел высказаться.

**3. Наблюдения (R2)** — если есть что фиксировать:

> «Мало успел высказаться» — это факт из конспекта или твоё ощущение? На встрече он говорил про бюрократию и админку — хочешь записать наблюдение?

После валидации — строка в таблицу **только с подтверждением**.

**4. Анализ поведения тимлида (R3):**

```markdown
## Как ты вела 1:1 — 23.06.2026, Дмитрий

### Что вижу в конспекте
- **Баланс:** ты подробно изложила ОС по коллегам и инциденту с кодом; у Димы было несколько развёрнутых ответов, но инициатива чаще у тебя.
- **Вопросы:** много уточняющих про ожидания; мало «что ты сам хочешь изменить?».
- **Обратная связь:** дала прямую ОС про осторожность с кодом — хорошо.

### Возможные зоны внимания
- В конце можно было спросить: «что для тебя главный итог встречи?»

### Что сработало хорошо
- Честный разговор про зоны роста без ухода в конфликт.
```

**5. Рекомендации (R4):**

```markdown
## Рекомендации для тебя

1. **Больше паузы после ОС** — дать Диме сформулировать своё видение.
2. **Peer feedback** — на следующем 1:1 проверить: пришли ли анкеты, что он думает.
```

**6. Сохранение (R5):**

> Сохранить разбор в leadership/kamilla-saidova.md?

## Сценарий 2: Подготовка к 1:1

### Ввод пользователя

```
@1-1 подготовься к 1:1 с Димой Гуминиченко
```

### Фаза A — агент выдаёт сводку (фрагмент)

```markdown
## Сводка: Дмитрий Гуминиченко — подготовка к 1:1

**Последний 1:1:** 23.06.2026 — итоги первого месяца, взаимная ОС, peer feedback
**Профиль:** web, испытательный срок до 17.08.2026, ментор — Горовой Иван

### Открытые договорённости
- 20.05.2026 — история с автотестами (прокопать) — ⚠️ follow-up 10.06 прошёл
- 23.06.2026 — peer feedback через анкеты (Камилла)
- 23.06.2026 — переспрашивать при непонимании контекста

### Action items (незакрытые)
- Камилла — отправить анкеты peer feedback (23.06)
- обоим — вернуться к предпочтениям по задачам

### Наблюдения и риски
- 03.06 риск — удаление кода без проверки (обсуждали 23.06)
- 23.06 рост — осторожнее с изменением существующего кода
```

### Фаза A2 — анализ (фрагмент)

```markdown
## Анализ: Дмитрий Гуминиченко

### Сильные стороны
- быстрое погружение в продукт, инициативность (наблюдения 20.05, 23.06)
- продуктовый подход — читает доку, задаёт вопросы (28.05)
- мотивируют зрелые процессы и качество кодовой базы (23.06)

### Зоны роста
- осторожность при изменении существующего кода (риск 03.06, обсуждали 23.06)
- больше контекста при объяснениях нетехническим коллегам (23.06)

### Чем живёт
- интересны продуктовые задачи как головоломка
- меньше бюрократии, чем на прошлом месте — важный мотиватор

### Пробелы в понимании
- куда хочет развиваться конкретно — «пока не выделил»
- предпочтения по задачам — договорились вернуться позже
```

### Фаза A0j — Jira (пример)

Период: с последнего 1:1 `23.06.2026` → сегодня. Отчёта за этот период нет → агент **предлагает** собрать анализ (не запускает CLI сам).

После подтверждения и готового отчёта:

```markdown
### Контекст из Jira

**Период:** 23.06.2026 — 07.07.2026
**Отчёт:** `notes/jira/reports/employees/guminichenko_d/….json`

#### Факты
- направления: web, …
- завершённые / незавершённые: …
- значимые: [CAT2-…](url)
- возвраты / долгие этапы: …
- кейсы: …

#### Гипотезы
- …

#### Вопросы для обсуждения
- «Как шла CAT2-… — где застряло?»
```

Если `is_developer` и есть MR — отдельно предложить Git-анализ; без «да» не запускать.

### Фаза B — рекомендации

```markdown
## Рекомендации к 1:1

1. **Прогресс по целям ИС** (осталось ~6 недель)
   Зачем: проверить, на треке ли к 17.08
   Вопрос: «Какие цели уже закрыл, где нужна помощь?»

2. **Повторяющийся риск с кодом**
   Зачем: 03.06 инцидент, обсуждали 23.06 — проверить изменения
   Вопрос: «Как сейчас подходишь к рефакторингу существующего кода?»

3. **Направление развития**
   Зачем: пробел — не выделил конкретное направление
   Вопрос: «Где интереснее — продукт, веб, админка, техинициативы?»

4. **Peer feedback**
   Зачем: action item с 23.06
   Вопрос: «Получил анкеты? Что ответили коллеги?»
```

> Отметь: да / нет / знаю — по каждому пункту.

**Пользователь:** `1 да, 2 да, 3 да, 4 нет знаю — анкеты ещё не отправила`

## Сценарий 1в: Follow-up по договорённостям

### Кейс A: мягкий follow-up без срыва

### Ввод пользователя

```
сделай follow-up по 1:1 с Марией и подготовь письмо

/Users/saidova_k/Downloads/2026-07-03 0959 (MSK) 0108750527.txt
```

### Что делает агент

1. Определяет сотрудника: **Кафанова Мария**.
2. Видит, что это первая фиксация без срыва → режим **мягкий**.
3. Формирует письмо:

```markdown
Тема: Follow-up по 1:1 от 03.07.2026

Привет!

Спасибо за встречу. Коротко зафиксирую, о чём договорились:

* на следующей неделе берёшь в работу CAT2-3700
* если по админке останутся сложности, заранее поднимаешь это в статусе

Что ожидаем по срокам:

* до 10.07 — старт по CAT2-3700
* при рисках по ходу — отдельный апдейт заранее
```

4. В приватную секцию дописывает:

```markdown
03.07.2026
  * **Контекст:** follow-up после 1:1 от 03.07.2026
  * **Режим письма:** мягкий
  * **Договорённость:**
    * взять в работу CAT2-3700 на следующей неделе
  * **Срок:** следующая неделя
  * **Статус:** в работе
  * **Факт по статусу:**
    * по итогам встречи договорённость подтверждена, признаков срыва на момент фиксации нет
  * **Обсуждали повторно:**
    * -
  * **Следующий шаг / новая договорённость:**
    * проверить старт задачи на следующем статусе
  * **Письмо:**
    * тема: Follow-up по 1:1 от 03.07.2026
    * отправлено: `[заполнить после отправки]`
  * **Ответ сотрудника:**
    * -
  * **Согласие по умолчанию:**
    * -
```

### Кейс B: официальный follow-up при повторном невыполнении

### Ввод пользователя

```
зафиксируй невыполненные договорённости после разговора с Димой и подготовь официальный follow-up
```

Пользователь дополнительно пишет:

```
Мы уже обсуждали, что он пришлёт peer feedback от коллег до 01.07, потом вернулись к этому на 07.07, но статуса так и не было.
Теперь договорились, что он пришлёт всё до 10.07.
```

### Что делает агент

1. Берёт из файла сотрудника старую договорённость.
2. Выбирает режим **официальный** — есть повторное невыполнение.
3. Формирует письмо:

```markdown
Тема: Follow-up по договорённостям после 1:1 от 07.07.2026

Добрый день!

Фиксирую итоги нашего разговора и договорённости.

**По пункту: peer feedback от коллег**

1. Ранее, по итогам 1:1 от 23.06.2026, мы договорились, что ты пришлёшь peer feedback от коллег до 01.07.2026.
2. На встрече 07.07.2026 мы вернулись к этому пункту. На тот момент итоговый статус и материалы не были предоставлены.
3. Мы повторно договорились, что ты пришлёшь peer feedback и краткий статус до 10.07.2026.

**Ожидаемый результат:**
* список полученного peer feedback от коллег
* краткий summary по основным темам
* срок: до 10.07.2026

Если видишь риск срыва срока или нужна помощь, пожалуйста, сообщи заранее.

Прошу подтвердить получение письма. Если у тебя есть замечания или возражения по зафиксированным договорённостям — напиши в ответ в течение 2 рабочих дней. При отсутствии возражений в этот срок договорённости, указанные в письме, считаем принятыми.
```

4. В приватную секцию дописывает:

```markdown
07.07.2026
  * **Контекст:** follow-up после повторного обсуждения договорённости с 1:1 от 23.06.2026
  * **Режим письма:** официальный
  * **Договорённость:**
    * прислать peer feedback от коллег
  * **Срок:** до 01.07.2026
  * **Статус:** не выполнено
  * **Факт по статусу:**
    * к 07.07 итоговый статус и материалы не прислал
  * **Обсуждали повторно:**
    * 07.07.2026 вернулись к теме на отдельном разговоре, сотрудник подтвердил, что вопрос не закрыл
  * **Следующий шаг / новая договорённость:**
    * прислать peer feedback и статус до 10.07.2026
  * **Письмо:**
    * тема: Follow-up по договорённостям после 1:1 от 07.07.2026
    * отправлено: 07.07.2026
  * **Ответ сотрудника:**
    * `[заполнить после срока]` / `ответа не было`
  * **Согласие по умолчанию:**
    * `-` (заполнить после 09.07.2026, если возражений не будет)
```

**После 09.07.2026** (если ответа не было) — обновить запись:

```markdown
  * **Ответ сотрудника:**
    * ответа не было
  * **Согласие по умолчанию:**
    * 09.07.2026 — возражений не поступило, договорённости считаем принятыми
```

### Важно

- Мягкий режим — без истории срывов и без блока согласия по умолчанию.
- Официальный режим — явная хронология, измеримый результат, подтверждение.
- «Согласие по умолчанию» фиксируется в приватной части только после истечения срока и при отсутствии возражений.
- Если сотрудник ответил с возражениями — это не согласие, фиксируем суть возражений.
- Если пользователь не дала статус, агент обязан уточнить его, а не додумывать.
