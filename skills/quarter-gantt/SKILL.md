# Quarter Gantt v2

Помогает **спланировать квартал**, а не заполнить анкету. Схема: [yaml-schema.md](yaml-schema.md). Команда: [team.md](team.md).

Токены не читать и не показывать. Jira и Confluence **только читать**. Ничего не менять и не публиковать во внешних системах. Даты, платформы, оценки не выдумывать. Неизвестный размер **не** заменять на S.

## Где лежат файлы

Каждый прогон — **одна папка** `features/gantt-runs/<время>__<quarter>/`:

```
features/gantt-runs/
  LATEST.md                         ← всегда начинай отсюда
  2026-09-08_20-06-08__Q4-2026/
    README.md
    yaml/base.yaml                  ← расписание (ещё optimistic / pessimistic)
    html/gantt-features.html         ← Гант по фичам
    html/gantt-people.html           ← Гант по людям
    report.md                       ← текстовая сводка
    trace.md                        ← откуда данные (если собирали)
```

Нужен последний прогон — открой `features/gantt-runs/LATEST.md`. Старые плоские файлы в корне `gantt-runs/` не трогать и не плодить; новый прогон только папкой.

Два HTML **обязательны**. Прогон без любого из них не готов. В чат — оба пути. На macOS: `open` **оба** html. Переключение «По фичам / По людям» есть в шапке каждого файла.

Mermaid в md и в чат не класть: Cursor его не рисует.

## CLI (корень репозитория)

```bash
pip3 install -r features/gantt/requirements.txt
python3 jira/get_issue.py CAT2-1234
python3 jira/search_issues.py --jql 'key in (CAT2-1234, CAT2-1370)' --limit 50
python3 features/gantt/fill_dates.py --input features/q4-2026-schedule.yaml
python3 features/gantt/render_gantt.py --input features/gantt-runs/<папка>/yaml/base.yaml --output features/gantt-runs/<папка>
```

Без `--output` `fill_dates.py` сам создаёт папку со штампом и обновляет `LATEST.md`.

Свежий отчёт Jira по тем же ключам **< 8 ч** — не перезапрашивать. Новый прогон планировщика — **новая папка** с временем в имени. Чужой YAML не перезаписывать без явной просьбы.

Идёт работа по уже существующей папке прогона — **не** начинать новый timestamp из‑за формата Ганта. Только `render_gantt.py` на `yaml/base.yaml` той же папки (оба html перепишутся). Планировщик заново не гонять, если состав и оценки не менялись.

## Пользовательский сценарий

Не начинать с длинного пакета вопросов и не вываливать сводку Jira.

### 0. Один главный вопрос (если ещё не ясно)

> Что строим:
> 1. всю корзину кандидатов, чтобы понять, что помещается;
> 2. план выбранных фич;
> 3. оба варианта?

Если из запроса очевидно — не спрашивать. Это задаёт `planning.goal`: корзина → `check_basket`; выбранный план → `maximize_priority` или `must`; оба — два прогона.

Критерий порядка вывести из запроса или спросить **одним** вопросом: больше приоритетных / must / короче сроки / вся корзина / ровная загрузка. Не спрашивать «в каком порядке остальные фичи».

### 1–4. Сбор (молча)

Файл, который назвал пользователь. Нет файла — спросить путь. Смежные карточки — только по ссылкам из файла.

Ключи Jira, дети, Blocks, оценки, платформы из prefix/component. Зонтик = стори/DSC, не каждый ребёнок отдельной фичей. «Не берём» не класть, если не просили всю корзину. Чужой проект — `external`, их спринт не раскладывать.

`teams/` по [team.md](team.md): только «в команде». Трассировку источников писать в `features/gantt-runs/<папка>/trace.md`, в чат — только если попросили объяснить данные.

### 5. Черновик без блокировки

Собрать YAML (оценки: exact / range / unknown). Не ждать всех чисел. `fill_dates.py` + `render_gantt.py` (report.md **и оба** html). Проверить, что в папке есть `html/gantt-features.html` и `html/gantt-people.html`. Обновить `LATEST.md`.

В чат **коротко**:

1. Помещается или нет.
2. Гант: два html в браузере (по фичам и по людям) + путь к папке и к `LATEST.md`. На macOS `open` оба.
3. Не попало в расписание.
4. Не оценено / неопределённости.
5. Узкие места.
6. Кто позже целевого релиза.
7. Чем optimistic отличается от pessimistic (если были диапазоны).
8. **Не больше трёх** следующих решений обычным языком (без кодов `Q-*`).

Счётчики: сколько фич, сколько оценено полностью, сколько частично, где дыры.

Подробности по одной фиче или группе — только следующим шагом, не 12 фич × все дорожки в одном вопросе.

«Гипотезы ок» не подтверждает пачку разнородных допущений: уточнять пакетами по три.

Discovery не называть оценённой разработкой: research отдельно, хвост `contingent` + unknown.

### Кадровый риск

Не умножать ёмкость на 0.5. Базовый Гант — факт. Сценарий «риск изменения ёмкости» — только если пользователь выбрал его одним из трёх решений.

## Чего не делать

- Не парсить план «из md сразу в картинку» без YAML и планировщика
- Не ходить в Jira без ключей из файла (кроме явной метки)
- Не коммитить `.env`
- Не путать со `sprint-review`
- Не запускать на реальном плане, если пользователь просит только доработать скилл
- Не использовать реальный Q4 в автотестах
- Не вставлять Mermaid-гант в md или в чат
- Не считать прогон готовым, пока нет обоих html: `gantt-features.html` и `gantt-people.html`
- Не сыпать одиночные yaml/html в корень `gantt-runs/`
