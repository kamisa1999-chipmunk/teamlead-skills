# Справочник — meeting-context

## Формат конспекта

См. `notes/1-1/reference.md` — тот же формат `.txt` в `~/Downloads/`.

## Определение групповой встречи

1. Извлечь спикеров (строки `Имя:` или `Имя (голос N):`).
2. Исключить `Саидова Камилла Зарифовна`.
3. Если остался **1** человек → 1:1, пропустить.
4. Если **2+** → групповая, обрабатывать.

## Поиск человека в конспекте

- По фамилии или подстроке из поля `**Имя** |`.
- Варианты в конспектах: `Гуминиченко Дмитрий Александрович`, `Гуминиченко Дмитрий Александрович (голос 1)`.

## Файл человека

Писать в `notes/teams/{гильдия}/{slug}/meeting-context.md`.

Копится. При повторном прогоне — **перезаписывать** блоки встреч на те же даты (обновление, не дублирование). Старые встречи не удалять.

## Формат блока (обязательный)

Каждая встреча — самодостаточный блок: пользователь должна понять **о чём встреча**, не открывая конспект.

Обязательные поля:
- ссылка на файл конспекта;
- «О чём встреча» (2–4 предложения);
- реплики человека с таймкодами `[ЧЧ:ММ:СС]`;
- «Итог для тимлида».

Таймкод = время **начала реплики** в конспекте → можно найти в `.txt` по поиску.

## Скрипт scan_transcripts.py

Возвращает JSON со списком встреч и сырыми репликами. Агент суммаризирует перед записью в файл.

```bash
python3 notes/meeting-context/scripts/scan_transcripts.py \
  --person "Гуминиченко" \
  --since 01.06.2026 \
  --downloads ~/Downloads
```

## Связка со скиллом 1-1

```
meeting-context  →  {slug}/meeting-context.md
                              ↓
1-1 (фаза A0)    →  с даты последнего 1:1; учитывает при анализе и рекомендациях
1-1 (сценарий 1б) →  после 1:1: рефлексия тимлида → leadership/kamilla-saidova.md
                              ↓
observations     →  наблюдения о сотруднике (с валидацией) из разбора 1:1
```

Рекомендуемый ритм: обновлять `meeting-context` раз в неделю или перед блоком 1:1.

## Связка со скиллом observations

`meeting-context` — подробный контекст для памяти.  
`observations` — короткие строки в таблице для ОС и действий.

После обновления контекста можно предложить: «зафиксировать наблюдения?» → `@observations`.
